## 10.1 `adaptive_palette.c/h` — runtime palette learning

**Responsibility.** "Enables runtime palette learning from captured images to handle camera color shift in 16+ color modes", combining "LAB color space for perceptual matching", "K-d tree for O(log n) color lookup", and "Color transform learning from finder patterns". <!-- anchor: adaptive_palette.h:1-12 -->

**Status, stated plainly:** no in-tree consumer calls this API. A symbol search across `src/` finds `adaptive_palette_*` only in `adaptive_palette.c` and `adaptive_palette.h`; the module is compiled into `libjabcode` by the `$(wildcard *.c)` source rule and its API is available to external consumers that include the header, but the library's own decode pipeline never invokes it. An earlier corpus-model draft recorded a "decoder → adaptive_palette" dependency edge; verification found neither a call nor an include from the decode pipeline, and the corpus model was corrected accordingly (2026-07-15) — [02-codec-pipeline.md](02-codec-pipeline.md) §2.3 records the same finding. Its status is library-for-consumers / dormant. <!-- anchor: grep adaptive_palette_ across src/: definitions and declarations only; src/jabcode/Makefile:21 -->

**State machine.** `jab_adaptive_palette` (h:53-64) holds expected/adapted palettes in RGB and LAB, the `kdtree_color*` lookup tree, the learned `jab_color_transform`, up to 8 `jab_color_sample`s, and flags. Lifecycle: *uninitialized* → `init` (adapted ≡ expected, tree built, `is_initialized`) → `add_sample`× (bounded at 8; silently ignored beyond) → `learn_transform` (`transform.is_valid`) → `apply_transform` (adapted diverges from expected; tree rebuilt) → `match`/`match_with_confidence`; `reset` returns to the post-`init` state without relearning; `free` invalidates. <!-- anchor: adaptive_palette.h:27-64; adaptive_palette.c:106-433 -->

**Transform model** (`jab_color_transform`, h:27-37): brightness offset on L\* (confidence-weighted mean of observed−expected L), saturation scale (mean observed/expected chroma ratio over samples with expected chroma > 5), hue rotation (mean hue shift in degrees over samples with both chromas > 10, normalized to ±180), gamma placeholder fixed at 1.0, and per-channel RGB scale factors (from samples whose expected channel exceeds 20; `use_per_channel` requires all three channels represented). `apply_transform` maps the *expected* palette forward through the LAB model (offset L, scale chroma, rotate hue) to predict camera-space colours; `match` applies the per-channel scales *inversely* to the observed sample before LAB conversion. Expected-palette generation duplicates the encoder's `genColorPalette` grid ("Matches encoder.c genColorPalette() exactly"), including the interval special case `(v−1)==3 → 85.0f`. <!-- anchor: adaptive_palette.c:156-281, 283-325, 327-353, 21-73 -->

## 10.2 `color_calibration.c/h` — static and FP-core colour calibration

**Responsibility.** An 8-slot standard↔calibrated RGB lookup with forward remap (encode-side: standard → device), inverse remap (decode-side: observed → standard), a JSON loader, and a builder that derives the calibration from a symbol's own finder-pattern cores.

**State.** One `static _Thread_local jab_color_calibration g_calibration = {0}` per thread. The threading caveat is normative for hosts: the per-decode FP-core path is thread-safe, "HOWEVER, a host that installs a *global* calibration profile out-of-band via jabApplyCalibration() / jabCalibrateFromObservedRGB() / jabLoadCalibrationFromJSON() must now do so ON EACH WORKER THREAD: the installed profile no longer propagates across threads". <!-- anchor: color_calibration.c:6-15 -->

**Public surface** (color_calibration.h:12-60):

| Item | Signature | Notes |
|---|---|---|
| `jabLoadCalibrationFromJSON` | `jab_int32 jabLoadCalibrationFromJSON(const char* json_string)` | Naive `strstr`/`sscanf` parser; requires all five keys `"red"`, `"green"`, `"blue"`, `"white"`, `"magenta"` with `"calibrated": [r,g,b]` arrays; K/Y/C are pinned canonical. Returns 1 on success, 0 otherwise. <!-- anchor: color_calibration.c:19-78 --> |
| `jabApplyCalibration` | `void jabApplyCalibration(jab_encode* enc)` | Forward remap of an encoder palette in place; no-op unless active and `color_number <= 8`. No in-tree caller (encoder does not invoke it). <!-- anchor: color_calibration.c:80-102 --> |
| `jabRemapColor` | `void jabRemapColor(const jab_byte* rgb_in, jab_byte* rgb_out)` | Forward exact-match remap, pass-through on no match or inactive. <!-- anchor: color_calibration.c:104-127 --> |
| `jabRemapColorInverse` | `void jabRemapColorInverse(const jab_byte* rgb_in, jab_byte* rgb_out)` | Inverse (observed → standard) exact-match remap, "symmetric to jabRemapColor". <!-- anchor: color_calibration.c:246-270; color_calibration.h:27-32 --> |
| `jabCalibrateFromObservedRGB` | `void jabCalibrateFromObservedRGB(const jab_byte observed[8][3])` | Installs observations by slot order `[0]=K, [1]=W, [2]=R, [3]=G, [4]=B, [5]=Y, [6]=C, [7]=M`; unobserved slots should carry the canonical colour so the inverse remap leaves them unmapped. Sets `is_active=1`. <!-- anchor: color_calibration.h:19-25, 36; color_calibration.c:142-165 --> |
| `jabBuildCalibrationFromFPCores` | `void jabBuildCalibrationFromFPCores(const jab_bitmap* matrix, jab_int32 color_number)` | Samples the module-space matrix at FP0's core (3, 3) for observed K; all other slots stay canonical. <!-- anchor: color_calibration.h:39-60; color_calibration.c:194-240 --> |
| `jabClearCalibration` / `jabHasCalibration` | `void ...()` / `jab_boolean ...()` | Zero the state / query `is_active`. <!-- anchor: color_calibration.c:129-135 --> |

**FP-core builder scope reduction (WS-4.5.1).** The header still documents Y/C sampling from FP2/FP3 for Nc≥2, but the implementation is K-only: "empirical verification via the WS-4.8 threshold sweep ... showed that the matrix samples at FP2/FP3 module positions do NOT reliably produce canonical palette colors in the intended slots — both ... orderings introduce regressions on at least one Nc level. ... Until that interaction is fully reverse-engineered, FP2/FP3 sampling is omitted here — K-only calibration is safe (palette\[0\]=K is canonical for all Nc)". The `color_number` parameter is retained but unused (`(void)color_number`). On clean input the observation equals canonical, so "calibration is identity → no behavioral change (Mode 1 Cassandra gate held by construction)". <!-- anchor: color_calibration.c:219-239; color_calibration.h:43-52 -->

**Decode-path integration — gated.** Two call sites exist in `decoder.c`, both under `USE_FP_CALIBRATION`: `jabBuildCalibrationFromFPCores` at the top of `decodeSymbol` (before any module sampling), and `jabHasCalibration()` + `jabRemapColorInverse` on each sampled module RGB in `decodeModuleHD`. With the gate undefined (all Makefiles — see the chapter head), the default decode path never touches calibration; the module's functions are nonetheless always compiled and exported, and `test/test_color_calibration.c` is the regression gate for the API itself. <!-- anchor: decoder.c:226-240, 725-736, 1874-1886; src/jabcode/test/test_color_calibration.c:14, 214-250 -->

## 10.3 `lab_color.c/h` — CIE LAB conversion and perceptual distance

**Responsibility.** RGB ↔ XYZ ↔ CIE L\*a\*b\* conversion (sRGB companding, D65 reference white `REF_X 95.047 / REF_Y 100.000 / REF_Z 108.883`, `LAB_EPSILON 0.008856`, `LAB_KAPPA 903.3`) and two perceptual distances: CIE76 (`delta_e_76`, Euclidean in LAB) and CIEDE2000 (`delta_e_2000`, full formula with G-factor, T weighting, and RT rotation term). The colour-space mathematics belongs to Special Topics (JC-S), forthcoming. <!-- anchor: lab_color.c:21-28, 90-146, 152-219, 224-231, 239-334 -->

**Public surface** (lab_color.h:26-126): types `jab_lab_color` (L 0–100, a/b −128..+127), `jab_xyz_color`, `jab_rgb_color`; functions `rgb_to_lab`, `lab_to_rgb`, `rgb_to_xyz`, `xyz_to_lab`, `lab_to_xyz`, `xyz_to_rgb`, `delta_e_76`, `delta_e_2000`, `find_nearest_color_lab` (linear scan by ΔE76). `lab_to_xyz` clamps inputs and scrubs NaN/Inf ("Validate output to prevent NaN/Inf propagation"). <!-- anchor: lab_color.h:26-128; lab_color.c:152-181, 339-357 -->

**Where the decoder actually uses it.** Directly, via `#include "lab_color.h"` under `USE_LAB_DISTANCE` in `decoder.c` — not through `adaptive_palette` (which is dormant, §10.1). When the gate is defined, `decodeModuleHD` classifies modules of `color_number > 8` symbols by `rgb_to_lab` + `delta_e_2000` against the palette panel, converting the sample once per module and each palette colour per comparison; "Nc<3 (modes 0,1,2 using normalized-RGB path) are untouched, preserving the Mode 1 regression gate by construction." Gate undefined in every Makefile → the default decode path performs no LAB work at all. Unconditional consumers of `lab_color` are `adaptive_palette.c` and `kdtree_color.c` (both themselves without pipeline callers) and the tests (`test_lab_color_distance.c`, WS-4.1). <!-- anchor: decoder.c:215-224, 752-792; adaptive_palette.h:18; kdtree_color.h:12; src/jabcode/test/test_lab_color_distance.c:2-35 -->

## 10.5 `decode_profile.c/h` — opt-in per-stage decode profiling

**Responsibility.** Attribute decode latency to the pipeline stages "so we can see WHICH stage dominates at low vs high Nc", gated behind a process-global flag with "default OFF = zero measurable overhead: a single global read short-circuits before any clock_gettime". <!-- anchor: decode_profile.h:7-16 -->

**Stages and sub-stages** (decode_profile.h:55-77):

| Enum | Members | Semantics |
|---|---|---|
| `jab_decode_stage` | `JAB_STAGE_DETECT`, `_PALETTE`, `_COLOR_CLASSIFY`, `_DEINTERLEAVE`, `_LDPC`, `_DATA_DECODE`, `_COUNT` | "additive — each is timed exactly where it executes, no subtraction". <!-- anchor: decode_profile.h:17-23, 55-64 --> |
| `jab_detect_substage` | `JAB_DET_BINARIZE`, `_FINDER`, `_TRANSFORM`, `_SAMPLE`, `_COUNT` | DETECT breakdown; "timed by JAB_PROF_DET_END, which folds each interval into both the sub-stage AND DETECT in one read, so DETECT == sum(sub-stages) by construction and there is no double counting". <!-- anchor: decode_profile.h:25-32, 70-77 --> |

**Accumulator.** `jab_decode_profile { jab_int64 stage_us[JAB_STAGE_COUNT]; jab_int64 detect_us[JAB_DET_COUNT]; jab_int64 decode_count; }` — microseconds per stage plus the decode-call count "so a caller can derive per-decode averages"; `decode_count` is incremented at the top of `decodeJABCodeEx`, including failed decodes. State lives in `decode_profile.c` as `unsigned char g_profile_stages = 0` and `jab_decode_profile g_decode_profile` — process-global, deliberately not `__thread`: "a diagnostic/benchmark tool flips it once, decode runs elsewhere; a torn read only mislabels one decode's timing, never affects the decoded bytes." <!-- anchor: decode_profile.h:79-94; decode_profile.c:18-28; detector.c:4074-4078 -->

**Macros.** `JAB_PROF_BEGIN(scope)` samples `CLOCK_MONOTONIC` only when the flag is set (scope-named local, so one function can host several non-overlapping timed stages); `JAB_PROF_END(scope, stage)` folds elapsed µs into `stage_us[stage]`, re-checking the flag "so a torn toggle mid-decode cannot fold a bogus interval"; `JAB_PROF_DET_END(scope, substage)` folds one reading into both `detect_us[substage]` and `stage_us[JAB_STAGE_DETECT]` ("DETECT sites use this macro instead of JAB_PROF_END, never both"). `jab_prof_now_ns` requires `_POSIX_C_SOURCE >= 199309L`, supplied on the compiler command line by the Makefile and defensively re-defined (guarded) in the header. <!-- anchor: decode_profile.h:96-133, 38-47; src/jabcode/Makefile:5-8 -->

**Public API** (jabcode.h:282-285): `jabSetProfileStages(jab_boolean)`, `jabIsProfileStages(void)`, `jabGetDecodeProfile(void)` (returns `const struct jab_decode_profile*` into the global — "do not free"), `jabResetDecodeProfile(void)` (memset). The header comment fixes the idiom lineage: "Mirrors the jabSetDiagVerbose / jabGetPreferredColorCount process-global idiom." <!-- anchor: jabcode.h:273-285; decode_profile.c:34-63 -->

**Call-site map.** Detector: binarize (detector.c:4086-4089), finder pass 1/2 (3739-3741, 3772-3774), re-binarize (3756-3766), side-size and perspective transform (3795-3797, 3810-3814), FP sample and AP resample (3826-3828, 3929-3931), slave find/transform/sample (3970-3998), data decode (4187-4189). Decoder: master/slave palette (decoder.c:2184-2186, 2394-2396), colour classification (1661-1685), de-interleave (1966-1968), payload LDPC (1978-1980). Metadata LDPC calls are not instrumented. <!-- anchor: detector.c:4086-4089, 3739-3998, 4187-4189; decoder.c:1661-1685, 1966-1980, 2184-2186, 2394-2396 -->

**Tooling.** `make profile` builds `build/bench_profile` from `test/bench_profile.c` ("attributes decode latency to the major pipeline stages ... across colour modes Nc=4..256"; JSON on stdout, two tables on stderr). `scripts/plot_stage_profile.py` renders one stacked bar per colour mode over the six stages; `scripts/plot_detect_substage.py` renders the DETECT sub-stage split, selecting records tagged `"detect_substage": true` and annotating the DETECT total, which equals "the sub-stage sum, by construction". Harness methodology is chapter 12 territory. <!-- anchor: src/jabcode/Makefile:107-119; src/jabcode/scripts/plot_stage_profile.py:2-31; src/jabcode/scripts/plot_detect_substage.py:2-34 -->

## 10.6 The WS-5 Heisenberg gate — verbose diagnostics

The gate's design rationale, quoted from the public header:

> WS-5 Heisenberg gate: verbose-only diagnostic logging.
>
> Wraps JAB_REPORT_INFO with a runtime check against g_diag_verbose. Use for per-iteration / per-frame markers that are high-volume (Nc_FALLBACK loop body, palette learning hashes, intermediate detection state). Use plain JAB_REPORT_INFO for terminal markers (FAIL_ATTR, DECODE_OK, final result) that should always fire.
>
> Caller toggles with jabSetDiagVerbose(1). Default OFF, so these markers don't fire — preserving the camera-thread decode budget in production builds. See decoder.c for the flag definition and docs/cassandra-register/H_partI_clean_data_failure.md for the investigation that motivated keeping the markers available but gated.
>
> Declared as the raw `unsigned char` underlying type (rather than jab_boolean, which is typedef'd further down this file) so the macro remains usable from sites that include only the early portion of this header.

<!-- anchor: jabcode.h:72-89 -->

Mechanics: `JAB_DIAG_INFO(x)` expands to `do { if (g_diag_verbose) JAB_REPORT_INFO(x); } while (0)`; `JAB_REPORT_INFO` itself is additionally verbose-gated in the non-`MOBILE_BUILD` variant. The flag is process-global by decision record — the earlier `__thread` design "was broken in practice" because the UI thread set the flag while the CameraX analyzer thread read its own thread-local copy, so "\[PartI_DIAG\] markers never fired across a 5-fixture ... capture session"; the documented worst case of the global is benign ("torn reads collapse to 'verbose state momentarily wrong by one frame'"). Cost basis for gating: each Android marker is "a synchronous \_\_android_log_print ... costing ~50-300 µs per call under load", and a failed decode with a full Nc ladder "emits ~24 such lines, adding ~1.5-7ms of binder overhead per frame". Setters: `jabSetDiagVerbose` / `jabIsDiagVerbose`. <!-- anchor: jabcode.h:66-67, 90-91, 247-256; decoder.c:50-96, 210-213 -->

## 10.7 Mode 0 (2-colour) — decode-side implementation points

Mode 0 is the fork's monochrome (Nc=0, {K, W}) extension; the clause map records that only 4- and 8-colour modes are standard-defined and "A 2-colour mode does not exist anywhere in the standard" — Nc=0 is a reserved/user-defined mode per the Table 6 user-defined-colour-mode clause the source cites. Encoder-side and capacity treatment is chapter 16 territory; the decode-side machinery is: <!-- anchor: corpus §4 (Mode 0 row); decoder.c:1283-1290 -->

- **Detector trigger.** `detectMaster` samples a ~16×16 pixel grid and computes mean chroma (`|r−g| + |g−b| + |r−b|`); `g_mode0_decode = (mean_chroma <= MODE0_MEAN_CHROMA_TOLERANCE)` with the tolerance 30 chosen after per-pixel-strict thresholds failed on real camera noise ("All 118 frames evaluated g_mode0_decode=0 under the per-pixel rule despite obviously being greyscale on average"). The flag is `_Thread_local` in `detector.c` with a matching `extern _Thread_local` in `decoder.c` ("a thread-local object has to be declared _Thread_local in EVERY translation unit"). <!-- anchor: detector.c:41-104, 3695-3732; decoder.c:134-142 -->
- **Finder-search adaptations.** Colour-exactness checks are skipped (FP rings alternate K/W, so "the crossCheckColor 'all pixels = R0' assumption ... doesn't hold at Mode 0"), and FP types — indistinguishable by colour when every core is K — are assigned by image quadrant: "TL=FP0, TR=FP1, BR=FP2, BL=FP3. This single-pass approach replaces sibling expansion (which collocated type labels at the same position, producing degenerate transforms)." `crossCheckPattern` returns after the green structural check. <!-- anchor: detector.c:1460-1490, 1543-1553, 1880-1908, 1994-2009, 963-972, 1033-1039 -->
- **Part I short-circuit** (decoder.c:1283 comment block; code 1307-1318). Nc is already known from the chroma probe; the standard pair decode would fail because "Mode 0's {K, W} palette produces pairs containing W (rgb=7), which is not in the table — every lookup returns the invalid-sentinel 8". The four Part I modules are cursor-skipped, `Nc = 0` asserted, and Part II proceeds normally at `bits_per_module = Nc + 1 = 1`. `decodeModuleNc` gains a luminance branch (`< 127 → 0, else 7`) and the validity set switches to {0, 7}. <!-- anchor: decoder.c:1283-1318, 927-949, 1371-1392 -->
- **Master palette synthesis** (decoder.c:2206 comment block; code 2232-2248). `readColorPaletteInMaster` "wrote garbage palette values from finder-pattern positions assuming a color mode"; the implicit palette {K=(0,0,0), W=(255,255,255)} is written over all four panels "so the downstream pipeline ... works without per-function Mode 0 awareness." The cursor is already correct because the metadata-palette loop is vacuous at `color_number = 2`. <!-- anchor: decoder.c:2206-2248 -->
- **Slave palette synthesis** (decoder.c:2404 comment block; code 2421-2437). Identical overwrite for the cascade path — `readColorPaletteInSlave` succeeds vacuously but samples "docking-AP positions under a colour-mode assumption"; same layout, same rationale, per-panel K/W. <!-- anchor: decoder.c:2404-2437 -->

Detector implication beyond the listed bypasses: quadrant-based typing assumes the symbol is roughly axis-aligned and centered in the frame — a rotated or off-center monochrome capture can mis-type FPs, which the colour path would have disambiguated. This is inherent to the single-pass design choice recorded at detector.c:1994-1998. <!-- anchor: detector.c:1994-2009 -->

## 10.8 Interop consequences vs the ISO reference decoder

Verified statement, per extension. None of the modules in this chapter changes the wire format: nothing here alters the encoder's seeds, tables, placement, masking, or metadata construction ([04-encoder.md](04-encoder.md), [06-ldpc.md](06-ldpc.md), [07-mask.md](07-mask.md), [08-interleave-and-prng.md](08-interleave-and-prng.md) own those surfaces). Each extension is decode-side tolerance or tooling:

| Extension | Wire format | Consequence vs ISO reference decoder |
|---|---|---|
| Adaptive palette (§10.1) | Unchanged — no pipeline call site at all | None in default builds; an external consumer that adopts it changes only its own classification tolerance. <!-- anchor: §10.1 grep finding --> |
| Colour calibration (§10.2) | Unchanged — decode-side remap of *sampled* RGB; `jabApplyCalibration` (encode-side palette rewrite) has no in-tree caller | Dormant by default (`USE_FP_CALIBRATION` undefined). If built in and active, it normalizes observations before classification; symbols remain decodable by the reference decoder because emitted bytes never change. A host that used `jabApplyCalibration` to print device-adjusted palettes *would* deviate from the Table 21 default palette — that path is unexercised in-tree. <!-- anchor: decoder.c:725-736, 1874-1886; color_calibration.c:80-102 --> |
| LAB classification (§10.3) | Unchanged — alternative distance metric over the same sampled palette | Dormant by default (`USE_LAB_DISTANCE` undefined); affects only `color_number > 8` (reserved modes outside the ISO-defined 4/8-colour set anyway). <!-- anchor: decoder.c:215-224, 752-792 --> |
| k-d tree (§10.4) | Unchanged — lookup acceleration only | None; consumer-local. <!-- anchor: §10.4 --> |
| Decode profiling (§10.5) | Unchanged — timing accumulators around unchanged stages | None; "when disabled the timing call sites short-circuit on a single global read, so decode behaviour and timing are unchanged." <!-- anchor: jabcode.h:273-281 --> |
| Verbose diagnostics (§10.6) | Unchanged — logging only | None; observability only. <!-- anchor: jabcode.h:72-91 --> |
